# Канонические модели данных

## SourceDocument
Оригинал и его описание. `id`, `workspace_id`, `supplier_id?`, имя, detected MIME, размер, SHA-256, storage ref, импортирован в, lifecycle status. Бинарник immutable; повторная загрузка того же hash — dedup reference.

## ExtractedField
`field_key`, `raw_value`, `normalized_value`, тип, confidence 0..1 (может быть null), provenance, extractor/version, review status `unreviewed|accepted|corrected|rejected`, revision. `normalized_value` никогда не заменяет `raw_value`.

## Product
Каноническая товарная единица с брендом, производителем, атрибутами, идентификаторами и базовой единицей. Синонимы/локализованные имена расширяются отдельными записями.

## SupplierOffer
Предложение поставщика, привязанное к исходной строке. Цена относится к указанной упаковке и валюте; условия имеют validity interval. Поля могут быть частично неизвестны; UI показывает неполноту.

## Quantity & unit
**Реализовано (TASK_002, предварительно):** коды `pc, pack, set, sheet, bag, roll, m, m2, m3, l, kg, t` с размерностью и UCUM (`{piece}`, `m2`, `L`…); полный словарь утверждается в Phase 0.

**Преобразования (TASK_006, `domain/units.py`, таблица `units-2026.1`):** стандартные коэффициенты только внутри одной величины (`t→kg` ×1000, `l→m3` ×0,001); счётные единицы (шт, уп, меш, рулон…) между собой и в меры не переводятся. Фасовка (`Pack`: единица цены, содержимое `Quantity`, источник `stated|name|user`, фрагмент текста, `confirmed`) — свойство предложения: прочитанная из названия («мешок 50 кг», «уп. 500 шт.», «, 14 кг») — только подсказка, не подтверждена; размеры («12,5 мм», «1200×2500», «3×100 м», «6 м» у профиля) фасовкой не считаются. `Conversion` хранит коэффициент, метод `identity|standard|packaging`, версию таблицы и `confirmed`.

Quantity хранится decimal; единицы кодируются контролируемым словарём (UCUM-совместимый где применимо) и локализованной подписью. Преобразования имеют источник/версию и запрещены между несовместимыми размерностями.

## Match
Suggestion содержит оценку и признаки; decision — отдельная запись пользователя/правила. Переопределения создают новую decision с supersedes; исходная связь предложения сохраняется.

**Реализовано (TASK_006, domain only, `domain/matching.py`, версия `match-2026.1`):** `Candidate` = оценка 0..1 + признаки `{code, weight, detail, blocking}`: `GTIN_EQUAL` (+0,6), `SUPPLIER_SKU_EQUAL` (+0,5, только артикул *этого* поставщика), `SKU_OF_OTHER_SUPPLIER` (0, пояснение), `MANUFACTURER_CODE_EQUAL` (+0,3), `NAME_TOKENS` (до +0,6), `ATTRIBUTE_EQUAL` (+0,1); блокирующие `GTIN_CONFLICT`, `ATTRIBUTE_CONFLICT` (марка М400 ≠ М500, размеры), `PACK_CONFLICT` (25 ≠ 50 кг у товара, учитываемого в штуках/мешках); `PACK_DIFFERS_NORMALIZABLE` — другая фасовка товара, учитываемого в кг/л/м², не конфликт; `UNIT_INCOMPATIBLE` (−0,3). Названия сравниваются по ключу (регистр, ё/е, латинские двойники, «о»→«0» в числах, ×/x/х), исходный текст не меняется. Заблокированный кандидат получает оценку 0, но показывается с причиной. `MatchDecision` (`accept|reject|revoke`, actor `user:…`/`rule:…@версия`, reason, `supersedes_id`, снимок кандидата, `override`) — только добавление; одно активное сопоставление на предложение; подтверждение заблокированного требует причины; правило не может подтвердить конфликт. `AutoLinkPolicy` выключена по умолчанию; при заданном пороге связывает только при совпадении идентификатора (GTIN или артикул этого поставщика) и не повторяет отклонённое.

## Cost snapshot
Immutable input snapshot + policy/formula version + компоненты + результат + warnings. Пересчёт создаёт новый snapshot; курс FX и его дата/источник копируются внутрь расчёта.

**Реализовано (TASK_006, domain only, `domain/costs.py`, формула `landed-2026.1`):** количество в базовой единице переводится в единицы цены через `Conversion` и округляется вверх до целых (счётные единицы), кратности и минимального заказа (излишек — предупреждение). Компоненты применяются в заданном порядке: `per_order`, `per_unit` или процент от явной базы `goods_gross | goods_net | subtotal`; виды `discount` (вычитается), `delivery`, `insurance`, `vat`, `duty`, `fee`, `other`; статус `known | unknown | not_applicable`. НДС и пошлина без источника ставки не принимаются; НДС не добавляется сам и не считается возмещаемым; НДС поверх цены «с НДС» — ошибка. Каждый компонент округляется до минорной единицы валюты (half-up; JPY 0, KWD 3), итог = сумма округлённых, стоимость базовой единицы = итог ÷ купленное количество, 4 знака. Курс `FxRate` (base, quote, rate, effective_date, source): прямой или обратный (с предупреждением), не позже даты расчёта; старше 7 дней — предупреждение; нет курса — итог не считается. Предупреждения: `MISSING_COST_INPUT` (по умолчанию обязательна доставка), `TAX_NOT_SPECIFIED`, `VAT_RECOVERY_NOT_ASSUMED`, `FX_MISSING|FX_STALE|FX_AFTER_DATE|FX_INVERTED`, `CONVERSION_UNCONFIRMED`, `PRICE_UNCONFIRMED`, `QUANTITY_ROUNDED_UP`; `complete = false`, если не хватает данных, курса или подтверждений. Снимок неизменяем, содержит JSON-копию входа (с использованными курсами) и `input_hash` (SHA-256); пересчёт — новый снимок с `supersedes_id`. Хранение в БД и API — следующий шаг.

## Валюты и локали
Использовать ISO 4217 codes, хранить locale tag (BCP 47), country code ISO 3166-1 alpha-2. Формат отображения — локальный, значение — каноническое. Не применять числовую локаль при парсинге без явной эвристики и проверки неоднозначности.
