# Архитектурные решения (ADR)

## ADR-001: Модульный монолит
**Статус:** принято. Ускоряет MVP и сохраняет возможность отделить worker/модули позднее. Модули имеют владельцев данных и публичные интерфейсы.

## ADR-002: Tauri 2 + React/TypeScript, FastAPI/Python
**Статус:** принято по решению владельца. Python удобен для локального OCR/парсеров; Tauri даёт desktop shell; API сохраняет опцию cloud deployment.

## ADR-003: SQLite local, PostgreSQL cloud
**Статус:** принято. Нужны portability discipline, тесты миграций и избегание engine-specific бизнес-семантики.

## ADR-004: Local-first, cloud AI opt-in
**Статус:** принято. Сетевой доступ не обязателен для базового workflow. Передача документов должна быть объяснена и разрешена явно.

## ADR-005: Общая платформа DIP, отдельный PricePilot
**Статус:** принято. Общие document intake/OCR/extraction/provenance могут быть переиспользованы. Бизнес-модели закупки отдельны. EstimateCheck не входит в продуктовый пакет требований.

## ADR-006: Оригинал неизменяем, corrections additive
**Статус:** принято. Extraction run и user correction создают версию/событие, обеспечивая воспроизводимость.

## ADR-007: Библиотеки foundation (TASK_001)
**Статус:** принято для MVP, пересмотреть при упаковке (TASK_005). Всё работает офлайн, без телеметрии.
- Backend: FastAPI (MIT), Starlette (BSD-3), Uvicorn (BSD-3), Pydantic (MIT), SQLAlchemy 2 Core (MIT), Alembic (MIT), platformdirs (MIT). FastAPI тянет `opentelemetry-api` (Apache-2.0) — только API, без экспортёров и сетевой отправки. Dev: pytest (MIT), httpx (BSD-3), ruff (MIT), mypy (MIT); окружение — uv.
- UI-шрифт: Onest (SIL OFL 1.1) из пакета `@fontsource/onest` — файлы шрифта входят в сборку, к Google Fonts и в сеть приложение не обращается.
- UI: React 19 (MIT), Vite 8 (MIT), TypeScript 5.9 (Apache-2.0; 5.x, так как openapi-typescript/typescript-eslint ещё не поддерживают 7.x), openapi-typescript (MIT), ESLint + typescript-eslint (MIT), Prettier (MIT), Vitest (MIT), `@tauri-apps/api` (MIT/Apache-2.0).
- Desktop: Tauri 2 (MIT/Apache-2.0), serde/serde_json, getrandom (MIT/Apache-2.0). Плагины Tauri не подключены.
- Импорт (TASK_003): openpyxl (MIT) в режиме read-only, формулы не вычисляются; defusedxml (PSF) — защита XML от billion-laughs/XXE, openpyxl подключает его автоматически. CSV — стандартная библиотека.
- OCR (dip-0.4.0): rapidocr (Apache-2.0), onnxruntime (MIT), opencv-python-headless (Apache-2.0), numpy (BSD), shapely (BSD), pyclipper (MIT), Pillow (MIT-CMU), модели PP-OCR (Apache-2.0) — см. ADR-011.
- Форматы (dip-0.3.0): python-docx (MIT), pdfplumber (MIT; pdfminer.six MIT, pypdfium2 Apache-2.0/BSD), xlrd (BSD) — только чтение, без выполнения макросов; xlwt (BSD) — только для тестов.
- PostgreSQL-драйвер: psycopg 3 (`psycopg[binary]`, LGPL-3.0, динамическая библиотека) — только extra `postgres` и dev-зависимость; локальная сборка его не требует.
- ORM-классы не используются: таблицы описаны SQLAlchemy Core, доменные сущности — dataclasses; репозитории в `infrastructure/db`.

## ADR-008: Запуск локального API и handshake
**Статус:** принято. Shell генерирует 256-битный токен на запуск и передаёт его в stdin процесса API (не в argv/env/файлах). API привязан только к `127.0.0.1` без параметра хоста; порт `0` выбирает ОС; готовность — JSON-строка в stdout. Stdin остаётся открытым: EOF (выход или падение shell) завершает API. Дополнительно: проверка `Host` и `Origin`, CORS только для UI origins, лимит тела. UI получает адрес и токен командой Tauri `backend_connection`; в браузерном dev-режиме токен добавляет Vite proxy, в бандл он не попадает. Миграции выполняются автоматически при старте; диалог миграции и backup — TASK_005.

## ADR-009: Хранилище оригиналов и фоновая обработка (TASK_003)
**Статус:** принято для MVP. Оригиналы — content-addressed `originals/<aa>/<bb>/<sha256>` в каталоге данных, атомарный rename из `incoming/`, режим read-only, проверка хэша при чтении; один файл хранится один раз. Очередь — состояние запусков в БД + один фоновый поток; после перезапуска прерванные запуски помечаются `INTERRUPTED` и повторяются. **Ограничение:** парсеры работают в процессе API (лимиты размера/строк/ZIP есть, жёсткого таймаута и изоляции процесса нет) — вынести в отдельный процесс в TASK_005.

## ADR-010: Упаковка desktop и runtime (TASK_005)
**Статус:** принято для MVP.
- **Sidecar:** backend собирается PyInstaller (GPL-2.0 с bootloader exception — распространение собранных программ разрешено) в один файл `pricepilot-api-<target-triple>` (`backend/packaging/build_sidecar.py`), Tauri кладёт его рядом с исполняемым файлом (`bundle.externalBin`). Миграции Alembic упаковываются как данные. PostgreSQL-драйвер в sidecar не входит. Первый старт ~3–5 с (распаковка one-file).
- **Конфигурация:** `tauri.bundle.conf.json` (bundle + externalBin) подключается только в `tauri build --config …`; dev и CI-проверки собираются без sidecar. Debug-сборка запускает backend через `uv`, release — sidecar; обе ветки компилируются всегда, CI прогоняет clippy и в release-профиле.
- **Надёжность:** оболочка наблюдает за sidecar и перезапускает его при аварийном выходе (не более 3 раз за 60 с, затем понятная ошибка); UI при сетевой ошибке один раз перечитывает адрес/токен и повторяет запрос. Один API на каталог данных (OS-lock `api.lock`, `ALREADY_RUNNING`).
- **Миграции:** вместо диалога — гарантированная копия: если существующая база отстаёт от кода, перед миграцией создаётся `backups/pricepilot-<ts>-before-<rev>.sqlite3`, UI показывает уведомление. Ручные копии — `POST /backups` (SQLite online backup); восстановление — `pricepilot-api restore <имя>` при закрытом приложении (текущая база сначала копируется). Оригиналы (`originals/`) неизменяемы и не входят в копию базы; полная копия — весь каталог данных.
- **Релизы:** `.github/workflows/release.yml` (вручную или тег `v*`) собирает macOS `.app/.dmg` и Windows NSIS. **Подпись и нотаризация — требование релизной стадии:** без секретов сборки неподписанные.
- **OCR-ресурсы:** модели входят в sidecar как данные (`pricepilot/dip/ocr/models`, ~18 МБ, ADR-011).

## ADR-011: Локальный OCR — RapidOCR (PP-OCR, ONNX)
**Статус:** принято 2026-11-13 после сравнения с Tesseract.
- **Движок:** RapidOCR 3.10.0 (Apache-2.0) на onnxruntime (MIT) в Python backend — очередь распознаёт документы независимо от того, открыто ли окно. Модели (Apache-2.0, PaddleOCR / RapidOCR): детектор `PP-OCRv6_det_small`, распознавание `eslav_PP-OCRv5_rec_mobile` (русский/восточнославянские + английский). Классификатор поворота отключён (переворачивал короткие слова вроде «лист»). Модели лежат в репозитории и в поставке, загружаются по явному пути — загрузчик моделей RapidOCR недостижим, сеть не нужна (тест запрещает сокеты во время OCR). Контрольные суммы и происхождение — `backend/src/pricepilot/dip/ocr/models/NOTICE.md`. Зависимости: opencv-python-headless (Apache-2.0), numpy, shapely, pyclipper (MIT), Pillow (MIT-CMU), pypdfium2 — размер sidecar растёт.
- **Сравнение** (11 изображений: 4 скана и 7 рендеров синтетических прайсов, 357 эталонных строк из XLSX/цифрового PDF; одна и та же постобработка для обоих движков; Tesseract — tesseract.js 7 из прототипа, rus+eng, PSM 6/4): строк полностью верно (название + единица + все цены) — RapidOCR 301, Tesseract 167; цены 355 / 341; названия 320 / 197; единицы 331 / 316; лишние строки 2 / 10; неверная цена без пометки — 0 / 0; время 17,8 / 27,7 с. На сканах: 51 / 18 строк полностью верно. Остаточные ошибки RapidOCR без пометки — посимвольные в названиях («М50о», «д500», «©12»): учитывать при сопоставлении (TASK_006).
- **Отклонено:** tesseract.js в окне приложения — привязывает обработку к открытому UI. Tesseract остаётся эталоном для повторных сравнений.
- **Правило безопасности:** единица, полученная исправлением OCR, и «м» со скана всегда требуют подтверждения; заголовок, определённый по содержимому, — тоже. Смена модели = новая версия pipeline и повторное сравнение.

## ADR-012: Сопоставление и полная стоимость — сначала домен (TASK_006)
**Статус:** принято 2026-11-13.
- Сопоставление — объяснимые правила (`match-2026.1`), без ML и внешних сервисов; веса признаков фиксированы и версионированы, изменение весов — новая версия. Конфликт упаковки или атрибутов блокирует, а не снижает оценку: разные товары не сливаются молча. **Автосвязывание выключено до проверки порога на реальных обезличенных прайсах** (решение владельца 13.11.2026): включить его можно только с записью о проверке для текущей версии сопоставителя.
- Формула полной стоимости (`landed-2026.2`) — доменный сервис с настраиваемой и расширяемой политикой компонентов; порядок компонентов и база процента задаются явно, а не угадываются по стране. Отсутствующее значение — «неизвестно», а не ноль: итог не показывается, пока есть неизвестные (решение владельца 13.11.2026). Налоги и пошлины — только явный ввод с источником или настроенный проверенный источник ставок, действующий на дату. Округление по компонентам, чтобы расшифровка всегда сходилась с итогом.
- Пересчёт единиц: стандартные коэффициенты — таблица `units-2026.1`; фасовка из названия — подсказка, расчёт с ней помечается неполным до подтверждения.
- Хранение (миграция 0004), API и экраны «Сопоставление» и «Сравнение» реализованы; кандидаты считаются по запросу и сохраняются в решении, отдельной таблицы подсказок нет.
