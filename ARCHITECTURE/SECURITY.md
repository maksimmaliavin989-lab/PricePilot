# Безопасность и приватность

## Модель угроз
Недоверенные входные документы, макросы/формулы, специально сформированные архивы, вредоносные изображения, локальные другие процессы, утечка через диагностику, ошибочная отправка в cloud AI, компрометация cloud credentials.

## Контроли
- MIME sniff по содержимому; allowlist расширений; лимиты размера, страниц, распаковки, строк и времени.
- Парсеры без исполнения макросов; сетевой доступ worker по умолчанию закрыт; изоляция процесса и временный каталог.
- Проверка zip-bomb/архивов; безопасные имена файлов; оригинал immutable и хранится отдельно от derived artifacts.
- Шифрование локального хранилища на уровне платформы/опциональный ключ; облако — TLS, шифрование at rest, разделение tenant.
- Секреты — системное хранилище ключей; не в БД, исходниках, логах.
- Минимальная телеметрия, локальная по умолчанию; редактирование путей/названий и чувствительных полей.
- Экспорт и удаление с явным подтверждением; удаление включает производные данные и индекс, с описанием ограничений backup.
- Cloud AI требует opt-in и audit event; только нужные поля/страницы.

## Аудит
Записывать кто/когда/что поменял (без полного документа в event), предыдущую/новую версию нормализованного поля и причину. События удаления и согласия на передачу защищать от обычного редактирования.

## Инциденты
Сбой парсера: изолировать файл, отметить статус, не терять оригинал. Подозрение на утечку: остановить интеграцию, отозвать ключи, определить затронутые документы/пользователей, зафиксировать временную шкалу и выполнить применимые обязанности после юридической проверки.
